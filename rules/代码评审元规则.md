# Code Review Meta Rules

这份文档不定义什么是好代码。
只约束模型在不确定时的判断偏向。

## 1. 默认沉默

评审默认结论是不修改。

任何修改建议都必须证明：
该修改解决具体问题，并且收益大于成本。

## 2. 只响应具体缺陷

不要主动寻找改进机会。

缺陷必须能对应到：
具体输入、状态或环境，
导致行为违反契约。

## 3. 自顶向下

审查顺序：

系统边界
→ 数据模型
→ 状态转换
→ 业务逻辑
→ 实现细节

前层没有问题，不深入下一层。

## 4. 不确定时选择克制

裁决顺序：

正确性 > 清晰 > 克制 > 风格偏好

## 5. 暴露取舍，不制造折中

存在真实冲突时，指出冲突。

不要通过增加复杂度强行兼顾。

## 6. 结论必须可验证

阻塞意见必须说明：

位置、
触发条件、
影响、
修复方向。

无法验证的风险降级为建议。

---

新增规则前：

只保留那些纠正模型默认偏差的规则。
不要重复已有工程知识。

保持规则集最小。
